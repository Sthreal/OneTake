# 仓库结构与开发说明

## 定位

One Take 是一个产品的单仓库发布源。仓库内部可以包含多个运行组件，但对外只维护一个 GitHub 项目、一套版本号、一套发布记录和一套回退标签。

## 目录职责

| 路径 | 职责 | 发布关系 |
|---|---|---|
| `apps/api/` | One Take 核心 FastAPI 服务 | 核心服务 |
| `apps/worker/` | RQ Worker、媒体处理和异步任务 | 核心服务 |
| `apps/mcp/` | 受控 MCP Bridge | 核心服务 |
| `apps/web/` | 已冻结的旧版 Web | 仅回退 |
| `platform/one-take-backend/` | One Take 产品后端、Agent Runtime 与当前产品 Web 宿主 | 内部平台 |
| `assets/readme/` | GitHub 首页主视觉、流程图和社交预览图 | 展示素材 |
| `docs/` | 架构、方案档案、验收和操作手册 | 文档 |
| `infra/` | 数据库和基础设施配置 | 开发与部署 |
| `scripts/` | 验收、构建和维护脚本 | 开发工具 |

## 对外名称与内部名称

对外文档和 UI 使用：

- One Take
- One Take 产品后端
- One Take Agent Platform

内部代码为了兼容历史版本，暂时保留：

- `miniclaw` 目录、包名和部分 API 路径
- `MINICLAW_*` 环境变量
- `/miniclaw-api` 和 `/miniclaw-ws` 代理路径

这些内部名称不代表第二个产品仓库，只代表需要兼容的运行接口。

## 单仓库规则

1. 所有产品提交进入 One Take 仓库，不再单独提交 MiniClaw 产品仓库。
2. 新增代码必须先判断属于 Core、Agent Platform、Web、文档还是基础设施。
3. 不把 `.env`、用户素材、Workspace 数据、日志、数据库或生成结果提交到 Git。
4. 不创建 Git Submodule。
5. 不删除历史回退标签和旧版 Web。
6. 发布前必须验证至少一个完整业务链路。

## 同步内部平台

`platform/one-take-backend/` 通过 Git Subtree 并入。同步上游时要使用单独分支：

```powershell
git switch -c codex/subtree-sync
git subtree pull --prefix=platform/one-take-backend <remote> <ref>
```

解决冲突后执行：

```powershell
docker compose exec -T api pytest -q
cd platform/one-take-backend
npm run typecheck
npm test -- --run
npm --prefix web run test:run
npm --prefix web run build
```

验证通过后再合并并打标签。出现不可解决问题时，回退到合并前的 One Take 标签或产品后端标签。

## 开发启动顺序

1. 启动 `api`、`worker`、`mcp` 和外部依赖。
2. 启动 `platform/one-take-backend` 的产品后端。
3. 启动 `platform/one-take-backend/web` 的产品 Web。
4. 通过 One Take Web 访问 Core API 和产品后端，不在浏览器中直接访问内部服务端口。

## 发布检查

```powershell
git submodule status
git ls-files | Select-String -Pattern '(^|/)\.env($|\.)'
git status --short
```

期望结果：

- `git submodule status` 无输出。
- `.env` 搜索无结果。
- 工作区没有意外修改。
- 只存在一个 GitHub remote。

## GitHub 首页规范

- `README.md` 第一屏必须展示产品主视觉、一句话价值主张、核心 CTA 和状态 badge。
- 首页优先回答“这个产品能做什么、给谁用、怎么开始”，仓库目录和技术细节放在后面。
- 主视觉、流程图和社交预览图统一放在 `assets/readme/`，不依赖外部图床。
- GitHub About 简介必须与 README 首屏使用同一产品定位，不能继续以 MiniClaw 作为主标题。
- 新功能完成后同步更新 Roadmap、测试命令和截图或流程图。
