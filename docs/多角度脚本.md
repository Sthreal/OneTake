# 多角度脚本

一次 `POST /api/v1/projects/{project_id}/script/generate` 固定产出 3 套口播候选，不再只落一条稿。三个角度是：

| `angle` | 名称 | 写在哪 |
|---|---|---|
| `pain_point` | 痛点种草 | 只在文案 |
| `scene` | 场景安利 | 只在文案 |
| `comparison` | 对比测评 | **只在文案**。不会写入 content_plan 的画面 `style` |

`comparison` 和合规里禁止的画面风格同名。分镜风格表仍然没有 comparison / 对比测评 / 开箱。选中这一条口播，不会多出一档对比画面。

## 怎么出 3 套

请求体和以前一样，只交痛点、卖点和场景。服务端自己展开三角，不接受自定义角度列表。

```http
POST /api/v1/projects/{project_id}/script/generate
```

```json
{
  "pain_point": "清洗麻烦",
  "selling_points": ["杯身可拆卸"],
  "usage_scenario": "通勤和办公室"
}
```

`202` 的 `data`：

- `candidates[]`：3 条，按角 0→2 排列。每条有 `angle`、`angle_label`、`version_id`、`generation_batch_id`。
- `selected_version_id`：默认是角 0（`pain_point`）。
- `version`：就是这条选中稿。旧客户端不读 `candidates` 时，看到的仍是角 0。

同一批用 `facts.generation_batch_id` 串起来，角度记在 `facts.angle`。不新增表。

Mock 下三个角度的 hook 和场景句不同：痛点用「还在为…」，场景用「怎么还不用…」，对比用「别再…」。不调用付费模型。

## 怎么选定、再确认

生成完成（三条都是 `ready`）后：

```http
POST /api/v1/projects/{project_id}/script/select
{"version_id": "<candidates 里要的那条>"}
```

选中的那条变成 `GET .../script` 的 `version`（latest）。然后：

```http
POST /api/v1/projects/{project_id}/script/confirm
```

只确认当前选中稿。同批另外两条保持 `ready`，不会变成 `confirmed`。已确认后再 select 会 `409 SCRIPT_CONFLICT`。

content_plan 仍读 latest，并且仍然要求文案已确认。未确认时生成分镜会被挡住；确认的是选中稿，不是另外两条。

正在排队时再打一次 generate，不会再插 3 条，还是返回这一批。这一批已经 ready 之后再 generate，才会开新的一批，默认角仍是新批的角 0。
