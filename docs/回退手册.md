# MiniClaw / One Take 回退手册

## 回退 One Take

```powershell
cd "D:\download new\ai_coding\0ne Take"
git switch --detach onetake-m1-stable
docker compose up -d --build
```

确认：

```powershell
docker compose exec -T api pytest -q
docker compose exec -T web npm run test:run
docker compose exec -T web npm run build
```

## 回退 MiniClaw

```powershell
cd "D:\download new\ai_coding\miniclaw-onetake"
git switch --detach miniclaw-base-v1
npm ci
npm --prefix web ci
npm --prefix container/agent-runner ci
npm run typecheck
npm run build:all
```

## 运行回退顺序

1. 关闭 MiniClaw 集成开关。
2. 停止 One Take MCP 服务。
3. 恢复 One Take 到 `onetake-m1-stable`。
4. 恢复 MiniClaw 到 `miniclaw-base-v1`。
5. 验证 One Take API、Worker 和 MinIO 正常。
6. 验证 MiniClaw 不依赖 One Take 即可启动。

## 数据回退

- P0 没有数据库迁移。
- 不删除对象存储中的任何媒体。
- 后续新增数据库字段必须使用 nullable/expand-contract。
- 回退前必须备份 PostgreSQL。
- MCP 和集成层的幂等记录不能用于替代 One Take 项目数据。

## 禁止事项

- 不读取或修改 `.env`。
- 不在未确认时执行真实付费调用。
- 不删除旧前端、媒体对象或历史标签。
- 未经明确要求不 push。

## P6 运行模式回退

P6 产品模式只启动 MiniClaw Backend：

```powershell
cd "D:\download new\ai_coding\miniclaw-onetake"
npm run dev:backend
```

需要临时调试 MiniClaw 自带 Web 时，可以回退为完整开发模式：

```powershell
npm run dev:all
```

注意：

- `npm run dev:all` 会占用 `5173`，与 One Take Web 冲突。
- P6-01/P6-02 没有数据库迁移和媒体变更。
- P6-03 将 SQLite schema 升级到 v70，只新增 `workspace_external_refs` 表和索引；升级前会自动生成 v69→v70 备份。
- 回退代码时保留该表和映射数据，不执行数据删除；旧版本忽略该表即可。
- 回退不需要删除 One Take 或 MiniClaw 的任何数据。
- 关闭 One Take Agent 面板时，在 One Take 仓库外层终端设置 `VITE_MINICLAW_ENABLED=false`，再重建 Web 容器：

```powershell
cd "D:\download new\ai_coding\0ne Take"
$env:VITE_MINICLAW_ENABLED = "false"
docker compose up -d --force-recreate web
```

- 恢复 Agent 面板时，把 `VITE_MINICLAW_ENABLED` 设为 `true` 或移除该环境变量后重建 Web 容器。

## P6-05 目录合并回退

P6-05 之前已创建标签：

```powershell
cd "D:\download new\ai_coding\miniclaw-onetake"
git show --stat miniclaw-onetake-pre-p6-05
```

需要回退目录结构时：

```powershell
git switch --detach miniclaw-onetake-pre-p6-05
```

回退说明：

- 该标签下 MiniClaw 原 Web 仍在 `web/`。
- 该标签下不存在产品 `web-miniclaw/` 和 One Take 产品 `web/` 的合并结构。
- One Take 原仓库和 `apps/web/` 不会被 P6-05 删除。
- 回退不删除数据库、媒体、用户会话或工作区映射。
- 重新切回集成分支即可恢复 P6-05 代码。
