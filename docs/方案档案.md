## M1-01：项目创建与 ProjectCreated 事件基线

### 状态

- 用户确认：是
- 实施状态：已完成
- 切片类型：后端垂直切片
- 依赖：无付费 AI Provider

### 一、目标

建立第一个可独立运行、可验证、可回滚的业务垂直切片：

```text
HTTP API
→ Project 应用服务
→ PostgreSQL project Schema
→ Outbox 事件
→ API 返回
→ 自动化测试
```

### 二、边界

本次要做：

- 定义项目创建和查询 API。
- 实现带前缀的项目 ID。
- 建立 `project` 和 `outbox` Schema。
- 使用 Alembic 管理数据库迁移。
- 实现 `project` 模块。
- 实现 `outbox` 模块。
- 创建项目时在同一事务写入项目和 `ProjectCreated`。
- 实现统一错误返回和请求 ID。
- 增加单元、集成和 API 契约测试。
- 修复 Web 健康检查的 IPv6/IPv4 误判。
- 保持现有 `/health`、Web、Worker、MinIO 和 Redis 正常运行。

本次明确不做：

- 不做素材上传。
- 不做 MinIO 预签名 URL。
- 不做 Pipeline 状态机。
- 不做 Job 队列。
- 不做 Mock 商品识别。
- 不接 Qwen、Photoroom、CosyVoice、Wan、Shotstack。
- 不做登录、支付、云端历史。
- 不删除已有 Docker、M0 文件和数据。

### 三、切片

#### 1. 接口

新增：

```text
POST /api/v1/projects
GET  /api/v1/projects/{project_id}
```

创建请求：

```json
{
  "product_name": "便携式榨汁杯",
  "product_note": "白色杯身，包装上有品牌文字"
}
```

创建响应：

```json
{
  "data": {
    "project_id": "prj_xxx",
    "product_name": "便携式榨汁杯",
    "product_note": "白色杯身，包装上有品牌文字",
    "status": "draft",
    "created_at": "...",
    "updated_at": "..."
  },
  "request_id": "req_xxx"
}
```

#### 2. 逻辑

- `Project` 领域对象。
- 初始状态固定为 `draft`。
- `product_name` 必填、去首尾空格、长度 1–80。
- `product_note` 可选、最长 240。
- 项目 ID 使用 `prj_` 前缀。
- 项目创建和事件写入必须处于同一事务。
- 事务失败时，项目与 Outbox 事件一起回滚。

#### 3. 工具

- SQLAlchemy 2 ORM。
- Alembic 迁移。
- PostgreSQL Session Factory。
- Pydantic Settings。
- UUID 生成器和带前缀 ID。
- 统一领域异常转换。
- 基础请求 ID 生成和日志。

迁移创建：

```text
project.projects
outbox.outbox_events
```

#### 4. 返回

Project 模块只公开：

```text
ProjectPublicService.create_project()
ProjectPublicService.get_project()
```

Outbox 模块只公开：

```text
OutboxPublicService.enqueue()
```

本次不实现 Outbox Publisher，只验证事件可靠落库。

### 五、验收标准

1. `docker compose up -d --build` 后所有现有服务健康。
2. `POST /api/v1/projects` 返回 HTTP 201。
3. 项目 ID 符合 `prj_` 前缀格式。
4. `GET /api/v1/projects/{project_id}` 返回相同项目和 `draft` 状态。
5. 查询不存在的项目返回 HTTP 404 和 `PROJECT_NOT_FOUND`。
6. `product_name` 为空时返回 HTTP 422，且数据库不新增项目。
7. `product_note` 超过 240 字时返回 HTTP 422。
8. 成功创建项目后，`project.projects` 新增 1 行。
9. 成功创建项目后，`outbox.outbox_events` 新增 1 行。
10. Outbox 事件名称为 `ProjectCreated`，`event_version=1`，状态为 `pending`。
11. 人为制造 Outbox 写入失败时，项目写入也必须回滚。
12. 每个请求返回唯一 `request_id`。
13. `pytest` 全部通过。
14. 现有 `/health`、Web、Worker、Redis、PostgreSQL、MinIO 无回归。
15. 不调用任何付费接口。
16. 本次改动可以单独回滚。

## 八段总结

### ① 解决了什么

解决“项目”这个核心概念从无到有的问题，并建立第一条 API、领域、数据库和 Outbox 可靠写入链路。

### ② 怎么实现的

采用模块化单体结构，`project` 负责项目和用例，`outbox` 负责事件落库。API 只负责协议转换，业务规则在 `domain`，事务和用例在 `application`，数据库实现放在 `adapters`，模块之间只通过 `public.py` 暴露能力。

### ③ 具体的实现方式

新增 `project` 与 `outbox` 模块。创建项目时，Project 服务和 Outbox 服务共享同一个 SQLAlchemy 事务。Alembic 创建 `project.projects` 与 `outbox.outbox_events`。API 使用 `/api/v1/projects`，请求中间件生成 `request_id`，异常统一转换为领域错误响应。

### ④ 为什么选择这种方式

该方式满足“一个概念一个模块”和“改一个功能不影响其他功能”。项目和 Outbox 分属独立模块，事务内写入避免项目和事件不一致，Alembic 管理长期数据库变更，公开接口防止模块内部互相侵入。

### ⑤ 有没有其他方式

有其他方式：

- 使用 `Base.metadata.create_all()` 自动建表。
- 将全部逻辑写在 `main.py` 或单个 `services.py`。
- 创建项目后直接发送事件，不使用 Outbox。
- 使用原始 UUID，不添加业务前缀。
- 只使用内存存储，不接 PostgreSQL。
- 将 Project 拆成独立微服务。

### ⑥ 为什么不选其他方式

- `create_all()` 无法可靠管理后续数据库变更。
- `main.py` 或 `services.py` 会破坏一个概念一个模块。
- 直接发事件可能导致项目存在但事件丢失。
- 原始 UUID 不利于日志追踪和外部接口辨识。
- 内存存储在服务重启后丢数据。
- 微服务对当前单机 MVP 过重，会增加网络、部署和调试成本。

### ⑦ 这种方式的难点是什么

- Docker 启动时可靠执行数据库迁移。
- 保证项目与 Outbox 同事务提交。
- 防止模块通过内部文件互相导入。
- 集成测试中隔离 PostgreSQL 和其他依赖。
- 保持现有 M0 服务和前端不回归。

### ⑧ 怎么能克服这种难点

- 在 Compose 中增加一次性 `migrate` 服务，API 和 Worker 等待迁移完成。
- 在同一个 SQLAlchemy Session 中写入 Project 和 Outbox。
- 使用 `public.py` 和导入检查限制模块边界。
- 使用独立测试数据库并回滚测试事务。
- 改动前运行健康基线，改动后运行 pytest、Compose 和健康检查。
- 每个切片独立提交，保留回滚点。
